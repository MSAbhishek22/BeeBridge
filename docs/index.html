How it works

Three steps. None of them are yours.

Every reminder app fails the same way: somebody has to set it up. BeeBridge removes the somebody.

1

Bee listens — once

The wearable captures the conversations that already happen: the doctor explaining the new dose, Priya confirming Sunday, the pharmacist's instructions. Consent-first, always — Bee's switch belongs to the wearer.

2

BeeBridge tidies the memory

Software reads each conversation and files away what matters: medicines (Metformin 500mg, with breakfast), appointments (Friday, 10am), promises & to-dos (bring the blood sugar log), and expectations (a package is coming tomorrow). No typing, no forms, no app to learn.

3

The house answers back

Ask Alexa+ out loud and get a clear answer. Glance at the TV for the day. And when Ring sees the expected package arrive, the announcement makes itself — and the to-do quietly completes. The memory maintains itself.

Conversation memory

Every captured conversation becomes searchable memory — facts, names, dates and instructions, kept word-accurate.

Medication answers

Promises inside conversations (“call Priya tomorrow”, “pick up vegetables Sunday”) become the day's list automatically.

For judges & developers

The engineering, briefly

BeeBridge is a Python/FastAPI service. Bee data enters through the real Bee CLI, the Bee MCP client, or Bee sync exports. Alexa+ talks to a self-hosted MCP server (Streamable HTTP, protocol 2025-11-25) with five tools; Ring events arrive by webhook; Amazon Bedrock (Converse) polishes summary wording when AWS is configured; the Fire TV UI is served at /tv. Extraction is deterministic — facts never hallucinate — and the whole pipeline runs from the bundled sample exports with no hardware.

Questions

Fair questions, straight answers

Do I need a Bee device to try it?

No. The repository bundles realistic Bee sync exports, so the full pipeline — extraction, questions, Ring matching, TV summary — runs on any computer in two minutes. Connect a real Bee and the same code ingests your own conversations.

Is it always listening? That sounds worrying.

Bee records only with the wearer's consent and has a hardware switch the wearer controls. BeeBridge adds nothing on top of that — and the memory it builds stays on the family's own computer, not in our cloud (there is no “our cloud”).

My parent is not technical at all. Really?

Really. There is nothing to install, open, type into or learn. They wear the Bee, they ask Alexa questions out loud, and the TV shows the day. If they can have a conversation, they can use BeeBridge — because the conversation is the interface.

What if the internet goes down?

The memory, the extraction and the answers all run locally. Alexa and Ring need their connections, but nothing about the memory itself depends on our servers — there are none.

How is this different from just asking Alexa to set reminders?

Somebody still has to remember to set the reminder — and remember what the doctor said well enough to dictate it. BeeBridge captures the source conversation itself, so the reminder exists before anyone thinks to create it, and the answer quotes what was actually said.
